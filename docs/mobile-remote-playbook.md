# スマホから Claude Code を使う運用ガイド(実測版)

作成: 2026-09-20 / 検証セッション: https://claude.ai/code/session_01BACw9VgziGecBeDcd8U5PG
検証方法: iPhone から起動したクラウドセッション内で、実際にコマンドを実行して確認した。
「実測」= このコンテナで確認済み。「公式doc」= 未実行、Claude Code ドキュメント記載。

## 結論

リポジトリの中で完結する作業は、スマホからでも普段どおりに回る。落ちるのは
「PC のローカル環境そのもの」に依存する作業だけで、その境界は明確に引ける。

- 回る: コード変更・テスト実行・調査・Web検索・Gmail/カレンダー/Drive参照・
  GitHub Issue 起票・MD への記録・コミット/プッシュ/PR・PR の CI 追従
- 落ちる: PC のファイル(リポジトリ外)、ローカルのアプリ操作、ブラウザ実操作、
  `~/.claude/CLAUDE.md` の個人メモリ
- 最大の落とし穴: **個人メモリ `~/.claude/CLAUDE.md` はクラウドに同期されない**(実測)。
  記憶を効かせたいなら、置き場をリポジトリ側に移す必要がある(後述)

## 1. 「スマホから」には別物が2つある

混同すると判断を間違えるので先に分ける。

| | クラウドセッション(このガイドの対象) | Remote Control (`/rc`) |
|---|---|---|
| 実行場所 | Anthropic のクラウドVM | 自分の PC |
| PC の状態 | **落ちていてよい** | 起動＋`claude` プロセス常駐が必須 |
| 見えるファイル | GitHub から clone したリポジトリのみ | PC のファイル全部 |
| 個人メモリ `~/.claude/CLAUDE.md` | **届かない**(実測) | 効く |
| ローカル MCP / ローカル設定 | 届かない | 効く |
| 起動 | Claude アプリの **Code タブ** | PC で `claude --rc` または `/rc` |
| 向く場面 | 手元にスマホしかない / PC が落ちている | PC は動いているが手元はスマホ |

出典(公式doc): https://code.claude.com/docs/en/claude-code-on-the-web ,
https://code.claude.com/docs/en/remote-control

**使い分けの既定値**: PC が起きているなら `/rc` が上位互換。PC に触れない/落ちている
ときだけクラウドセッション。ただし「PC を起こしに行けない」状況を想定するなら、
クラウドセッション単体で完結できる状態を作っておく必要がある(→ 3節)。

| 項目 | 実測結果 | 影響 |

### 2.3 ローカルとの差が実質ゼロだったもの

「普段の使い方と遜色ないか」への直接の答え。以下は今回のセッションで実際に通った。

- 会話の MD ファイル化 → このファイルがそれ
- 記憶への反映 → リポジトリ `CLAUDE.md` への追記(3節)
- GitHub Issue(ai-todo)の起票 → `mcp__github__issue_write` で実行可
- コミット → プッシュ → ドラフト PR 作成 → PR 監視登録
- 調べもの(Web検索 + 公式doc取得 + 実環境での裏取り)

## 3. 記憶をスマホから効かせる方法

クラウドセッションに `~/.claude/CLAUDE.md` は届かない。したがって
**「クラウドセッションにとっての記憶 = リポジトリにコミットされたファイル」** になる。

効く置き場は3つ。上から優先度が高い。

1. `<repo>/CLAUDE.md` — 毎セッション自動で読み込まれる。運用ルールの本体
2. `<repo>/AGENTS.md` — 同上(他ツール互換)
3. `<repo>/docs/*.md` — 明示的に参照させる補助資料(このファイル)

現状の問題(2026-09-20 実測):

1. このリポジトリの `CLAUDE.md` には「正本は `~/.claude/CLAUDE.md` の ai-todo 節。
   齟齬があればそちらが優先する」と書かれているが、**クラウドセッションからは
   その正本が読めない**。コピーがドリフトしても検知できない
2. 個人ナレッジの `kota-md` は GitHub に無い。セッションから到達できるリポジトリは
   `KotaHiguchiKH/kpi-compass-build-week` と `KotaHiguchiKH/yosoku` の2つだけだった。
   つまり **自己分析・過去の決定・就活の文脈はクラウドセッションから参照できない**
3. この結果、スマホから投げられるのは「このリポジトリの文脈で完結する作業」に限られる。
   例えば「自己分析(#233)を踏まえてESの下書きを作る」は、
   ローカルなら通るがクラウドセッションでは材料が無い

→ 置き場をどうするかはオーナー判断のため Issue 化した: #276 `[要相談]`

### 他リポジトリを引き込む方法(判断が出るまでの暫定)

セッション中に `add_repo` でリポジトリを追加できる。GitHub 上にあるものに限る。
スマホからは「`KotaHiguchiKH/yosoku` も見て」と書けばよい。

## 4. スマホからの投げ方(実用テンプレ)

音声入力で長く喋っても通る。構造化はこちら側でやる。最低限これだけ含める。

```
【やること】<動詞で1行>
【対象】<リポジトリ名 / ファイル / Issue番号>
【終わり方】<コミットまで / PRまで / 調査結果を報告だけ>
```

タスク種別ごとの推奨:

| やりたいこと | スマホからの出し方 |
|---|---|
| コード修正 | そのまま投げる。「PRまで」と書けばドラフトPRまで到達する |
| 調べもの | 「調べて docs/ に MD で残して」と付ける。チャットだけだとVM回収で消える |
| 会話の記録 | 「この会話を docs/ に MD で残して」。→ コミットされるので次回以降も読める |
| 記憶に残す | 「CLAUDE.md に追記して」。個人メモリではなくリポジトリ側に入る |
| ai-todo 起票 | いつもどおり。ラベル `ai-todo` 付き Issue が立つ |
| PR の面倒見 | 「このPRのCIを見て直して」。イベント購読して自動で追従する |
| PC の操作が要る作業 | **投げない**。`/rc` に回すか、ai-todo Issue にして手元でやる |

### 落ちないための注意

- **チャットの出力だけで終わらせない。** VM は無活動で回収される。残したいものは
  必ず「ファイルにしてコミットして」まで言う(このリポジトリは Stop フックが
  未コミットを検出するので、ほぼ自動で守られる)
- 長時間タスクはアプリを閉じてよい。セッションはクラウドで走り続ける(公式doc)
- プッシュ通知を受けたいなら iOS の Focus / 通知要約でブロックされていないか確認
  (設定 → 通知 → Claude)(公式doc)
- 途中で質問されたまま放置するとVM期限切れになりうる。再度開けば会話履歴は復元される(公式doc)
